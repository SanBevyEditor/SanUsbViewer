# San USB Viewer

**Українська** · [English](README.en.md) · [Français](../../README.md) · [50 languages](../README.md)

> Машинні переклади; виправлення вітаються.

**Поточна версія: `0.2.0`** — ліцензія MIT.

![San USB Viewer](../../assets/screenshots/SanUsbViewer.jpg)

Власний USB Explorer, написаний на **Rust**, із темним інтерфейсом, візуальною топологією та читабельною діагностикою. Перша версія призначена для Windows 10/11.

## Походження проекту

Відео на початку проекту: [https://www.youtube.com/watch?v=xk6GxQEmkus](https://www.youtube.com/watch?v=xk6GxQEmkus).

Проект заснований на використанні **WhatCable** в Apple і **USB Device Tree Viewer** в Windows: розуміння периферійних пристроїв, концентраторів і швидкості їх USB-з’єднань. Це самостійна реалізація.

## особливості

- Фактичне виявлення USB-пристроїв і контролерів через `nusb`.
- Деревоподібна структура автобуса та портового шляху, з глибиною вузла.
- Пошук за назвою, серійним номером або VID:PID; USB 3+ фільтри та концентратори.
- Договірна швидкість зв'язку: 1,5 / 12 / 480 Мбіт/с, 5 Гбіт/с,
або категорії SuperSpeedPlus (10 Гбіт/с або більше).
- Схема подорожі: комп'ютер, проміжні концентратори, зв'язок і пристрій.
- У Windows додаткове опитування концентратора IOCTL для з’ясування
Можливості SuperSpeed, анонсовані пристроєм. SuperSpeed-сумісний пристрій, підключений через USB 2.0, виробляє діагностику обмеження шляху.   Концентратори USB 2, які є супутніми концентраторами USB 3, розглядаються окремо, щоб уникнути приписування їх розгалуження 480 Мбіт/с несправності кабелю.
- Ідентифікатори VID/PID, дескриптор USB, версія, драйвер, послідовний номер та інтерфейси,
коли система розкриє цю інформацію.
- Автоматичне оновлення кожні три секунди або вручну за допомогою F5.
- Журнал сеансу останніх 200 спостережених змін.
- Експортуйте повний оператор у JSON (Ctrl+E) і скопіюйте вибрані деталі.
- Інтегрований посібник і демонстраційний режим, ніколи не використовувався як резервний
беззвучний у разі помилки виявлення.

## Кинути

З Rust **1.95+**, ланцюжком інструментів MSVC та інструментами Visual Studio C++ у Windows. У прикладах використовується RTK для фільтрації виводу команд; без RTK, просто видаліть префікс `rtk`. Сценарій розподілу приймає обидва випадки.

```powershell
rtk cargo run --release
```

Окремий двійковий файл створено в `target/release/san-usb-viewer.exe`. Сценарій `build.ps1` також створює розповсюдження в `dist/SanUsbViewer/`. Для інвентаризації не потрібно змінювати драйвер або інсталювати WinUSB: програмі не потрібні інтерфейси пристрою.

```powershell
# Démonstration avec données fictives, identifiées dans l’interface et l’export
rtk cargo run -- --demo

# Inventaire JSON sur la sortie standard (utiliser le binaire de développement)
rtk cargo run -- --scan

# Capture du rendu réel de l’application, puis fermeture automatique
rtk cargo run -- --screenshot artifacts/live.png
```

Цільова папка для захоплення має існувати. Випускна версія є безконсольною програмою Windows; віддайте перевагу `cargo run` у розробці для інвентаризації командного рядка.

## Інтерпретуйте результати

**Узгоджена швидкість** – це швидкість з’єднання, а не еталон швидкості копіювання. Корисні швидкості залежать, зокрема, від протоколу, периферійних та інших пристроїв, які спільно використовують шину. Швидкості з кількох пристроїв не сумуються для обчислення доступної пропускної здатності.

Пасивний USB-кабель, як правило, не є перерахованим пристроєм. Ця версія не зчитує свій електронний маркер, ані потужність USB Power Delivery, ані тип роз’єму. Тому він не претендує на сертифікацію своєї максимальної швидкості. Діагноз базується на спостережуваному зв’язку та, якщо є, на індикаторах Windows. Повільне з’єднання може бути обмежено кабелем, портом, концентратором або пристроєм. Номер версії дескриптора USB ніколи не використовується як максимальна швидкість.

Категорія SuperSpeedPlus тут не розрізняє режими 10 і 20 Гбіт/с. USB4/Thunderbolt та їхні тунелі не перевіряються. Порти без підключеного пристрою не інвентаризуються. Зарядний кабель без даних не створює видимого пристрою. В дереві USB можуть з’являтися внутрішні пристрої (Bluetooth, вбудована камера тощо).

Недоступна інформація відображається як недоступна. Windows не завжди розкриває виробника та інтерфейси. Події, які відбуваються між скануваннями, можуть залишитися непоміченими. Журнал знаходиться в пам'яті і починається після першої успішної інвентаризації.

Ідентифікатори шини та шляхи портів описують топологію системи. Фізичний роз’єм може мати два окремих шляхи для USB 2 і SuperSpeed.

## Архітектура та перевірка

`scanner.rs` проводить інвентаризацію; `windows_probe.rs` інкапсулює власні запити на читання від концентраторів; `model.rs` містить дані та діагностику. `app.rs` обробляє фонові завдання та вибір; `views.rs`, `inspector.rs`, `connection.rs` і `theme.rs` малюють інтерфейс за допомогою egui/eframe. Інтерфейс залишається інтерактивним під час сканування та зберігає останнє успішне зчитування, якщо наступне сканування не вдається.

```powershell
rtk cargo fmt --check
rtk cargo clippy --all-targets -- -D warnings
rtk cargo test --workspace
```

Бібліотеки є кросплатформними, а код Windows є умовним. Версії macOS/Linux не перевірені в цій першій доставці.

## Конфіденційність

Інвентаризація працює локально, лише для читання, без телеметрії чи мережевих служб. Посилання на посібник відкриваються лише після натискання. Звіти JSON можуть містити серійні номери та системні ідентифікатори: ділитися ними ви вирішуєте самі.

## Мови — версія 0.2.0

Додаток містить **50 мов інтерфейсу**. Натисніть код мови (`FR`, `EN` тощо) у верхньому правому куті, щоб відкрити перемикач. Ви можете шукати мову за її рідною назвою, англійською назвою або кодом. Зміна відбувається негайно, і вибір зберігається в `%APPDATA%/SanUsbViewer/preferences.json` під Windows. Без переваги використовується системна мова; Непідтримувана мова повертає англійську.

Вибір віддає перевагу мовам, які найбільше говорять загалом (рідній мові та другій мові), групуючи разом регіональні варіанти. Це не чисельна класифікація: результати різняться залежно від групування діалектів. Вибрані варіанти включають спрощену китайську, стандартну арабську та латинські шрифти фулані й узбецької; Панджабі використовує гурмукхі.

Англійська, китайська, хінді, іспанська, французька, арабська, бенгальська, португальська, російська, урду, індонезійська, німецька, японська, маратхі, в’єтнамська, телугу, хауса, турецька, пенджабі, суахілі, філіппінська, тамільська, перська, корейська, амхарська, тайська, яванська, італійська, гуджараті, каннада, бходжпурі, бірманська, польська, Йоруба, лінгала, оромо, фулані, малаялам, одія, українська, сіндхі, узбецька, пушту, сунданська, малайська, ігбо, непальська, азербайджанська, майтхілі та сомалійська.

Скопійовані меню, діагностика, довідкові тексти, повідомлення про дії та деталі локалізовані. Імена та ідентифікатори, надані апаратним забезпеченням і системою, зберігаються. Експорт JSON зберігає свою схему та дані інвентаризації незалежно від мови відображення. Технічні одиниці залишаються в **бітах/с** (Мбіт/с і Гбіт/с), щоб уникнути плутанини з байтами.

Французький та англійський каталоги служать довідкою. Інші мови є **автоматичними перекладами**, які можуть вимагати лінгвістичних виправлень. Файли `locales/*.json` включені в компіляцію, і їх можна виправити, а потім перекомпілювати. Додаток не здійснює мережевий переклад: вбудовано 50 мов і шрифти Noto відповідно до ліцензії SIL Open Font License. Арабський текст використовує двонаправлені сегменти Unicode та символи нового рядка, обчислені перед форматуванням.

```powershell
# Forcer une langue pour ce lancement, sans remplacer le choix enregistré
rtk cargo run -- --lang ja

# Vérifier les catalogues, les paramètres et les unités de vitesse
rtk python tools/validate_locales.py

# Capture du guide en arabe
rtk cargo run -- --demo --lang ar --page guide --screenshot artifacts/guide-ar.png
```

`SAN_USB_VIEWER_CONFIG` може посилатися на інший файл налаштувань для тестування або портативного встановлення. Там зберігається лише код мови.
