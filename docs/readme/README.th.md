Native USB Explorer เขียนด้วย **Rust** พร้อมอินเทอร์เฟซสีเข้ม โทโพโลยีแบบภาพ และการวินิจฉัยที่อ่านได้ เวอร์ชันแรกมีไว้สำหรับ Windows 10/11

## ที่มาของโครงการ

วิดีโอที่มาของโครงการ: [https://www.youtube.com/watch?v=xk6GxQEmkus](https://www.youtube.com/watch?v=xk6GxQEmkus)

โปรเจ็กต์นี้ได้รับแรงบันดาลใจจากการใช้งาน **WhatCable** บน Apple และ **USB Device Tree Viewer** บน Windows: ทำความเข้าใจเกี่ยวกับอุปกรณ์ต่อพ่วง ฮับ และความเร็วของการเชื่อมต่อ USB นี่คือการดำเนินการที่เป็นอิสระ

## คุณสมบัติ

- การตรวจจับอุปกรณ์ USB และตัวควบคุมจริงผ่าน `nusb`
- โครงสร้างแบบต้นไม้ตามเส้นทางรถบัสและท่าเรือ โดยมีความลึกของฮับ
- ค้นหาตามชื่อ หมายเลขซีเรียล หรือ VID:PID; ตัวกรองและฮับ USB 3+
- ความเร็วลิงก์ที่เจรจาไว้: 1.5 / 12 / 480 Mb/s, 5 Gb/s,
หรือหมวดหมู่ SuperSpeedPlus (10 Gb/s หรือมากกว่า)
- แผนภาพการเดินทาง: คอมพิวเตอร์ ฮับระดับกลาง ลิงก์ และอุปกรณ์
- ภายใต้ Windows การสอบปากคำเพิ่มเติมของฮับโดย IOCTL เพื่อค้นหา
ความสามารถของ SuperSpeed ที่ประกาศโดยอุปกรณ์ อุปกรณ์ที่รองรับ SuperSpeed ที่เชื่อมต่อผ่าน USB 2.0 จะสร้างการวินิจฉัยข้อจำกัดเส้นทาง   ฮับ ​​USB 2 ที่ใช้ร่วมกันของฮับ USB 3 ได้รับการปฏิบัติแยกกันเพื่อหลีกเลี่ยงไม่ให้สาขา 480 Mb/s เกิดจากข้อผิดพลาดของสายเคเบิล
- ตัวระบุ VID/PID, ตัวอธิบาย USB, การแก้ไข, ไดรเวอร์, อนุกรมและอินเทอร์เฟซ
เมื่อระบบเปิดเผยข้อมูลนี้
- อัปเดตอัตโนมัติทุกๆ สามวินาที หรือด้วยตนเองด้วย F5
- บันทึกเซสชันของการเปลี่ยนแปลงที่สังเกตได้ 200 รายการล่าสุด
- ส่งออกคำสั่งที่สมบูรณ์ใน JSON (Ctrl+E) และคัดลอกรายละเอียดที่เลือก
- คำแนะนำแบบรวมและโหมดสาธิตที่ชัดเจน ไม่เคยใช้เป็นข้อมูลสำรอง
เงียบในกรณีที่การตรวจจับล้มเหลว

## โยน

ด้วย Rust **1.95+** ห่วงโซ่เครื่องมือ MSVC และเครื่องมือ Visual Studio C++ บน Windows ตัวอย่างใช้ RTK เพื่อกรองเอาต์พุตของคำสั่ง หากไม่มี RTK เพียงลบคำนำหน้า `rtk` ออก สคริปต์การแจกจ่ายยอมรับทั้งสองกรณี

```powershell
rtk cargo run --release
```

ไบนารีแบบสแตนด์อโลนถูกสร้างขึ้นใน `target/release/san-usb-viewer.exe` สคริปต์ `build.ps1` ยังสร้างการแจกจ่ายใน `dist/SanUsbViewer/` ไม่จำเป็นต้องดัดแปลงไดรเวอร์หรือติดตั้ง WinUSB สำหรับสินค้าคงคลัง: แอปพลิเคชันไม่ต้องการอินเทอร์เฟซอุปกรณ์

```powershell
# Démonstration avec données fictives, identifiées dans l’interface et l’export
rtk cargo run -- --demo

# Inventaire JSON sur la sortie standard (utiliser le binaire de développement)
rtk cargo run -- --scan

# Capture du rendu réel de l’application, puis fermeture automatique
rtk cargo run -- --screenshot artifacts/live.png
```

ต้องมีโฟลเดอร์ปลายทางสำหรับการจับภาพ เวอร์ชันวางจำหน่ายเป็นแอปพลิเคชัน Windows ที่ไม่มีคอนโซล ต้องการ `cargo run` ในการพัฒนาสำหรับรายการบรรทัดคำสั่ง

## ตีความผลลัพธ์

**ความเร็วที่ต่อรอง** นั้นเป็นของการเชื่อมต่อ ไม่ใช่เกณฑ์มาตรฐานของความเร็วการคัดลอก ความเร็วที่เป็นประโยชน์นั้นขึ้นอยู่กับโปรโตคอล อุปกรณ์ต่อพ่วง และอุปกรณ์อื่นๆ ที่ใช้บัสร่วมกันโดยเฉพาะ ความเร็วจากอุปกรณ์หลายเครื่องไม่ได้นำมารวมกันในการคำนวณแบนด์วิธที่มีอยู่

โดยทั่วไปแล้วสาย USB แบบพาสซีฟไม่ใช่อุปกรณ์นับได้ เวอร์ชันนี้ไม่ได้อ่าน e-marker หรือกำลังส่งพลังงาน USB หรือประเภทตัวเชื่อมต่อ จึงไม่เรียกร้องให้รับรองความเร็วสูงสุด การวินิจฉัยจะขึ้นอยู่กับลิงก์ที่สังเกตได้ และ (หากมี) บนตัวบ่งชี้ Windows ลิงค์ที่ช้าอาจถูกจำกัดด้วยสายเคเบิล พอร์ต ฮับ หรืออุปกรณ์ หมายเลขเวอร์ชันตัวอธิบาย USB ไม่เคยใช้เป็นความเร็วสูงสุด

หมวดหมู่ SuperSpeedPlus ไม่ได้แยกความแตกต่างระหว่างโหมด 10 และ 20 Gb/s ที่นี่ USB4/Thunderbolt และอุโมงค์ไม่ได้รับการตรวจสอบ พอร์ตที่ไม่มีอุปกรณ์ต่ออยู่จะไม่ถูกจัดทำรายการ สายชาร์จที่ไม่มีข้อมูลไม่ได้สร้างอุปกรณ์ที่มองเห็นได้ อุปกรณ์ภายใน (บลูทูธ กล้องในตัว ฯลฯ) อาจปรากฏในแผนผัง USB

ข้อมูลที่ไม่สามารถเข้าถึงได้จะแสดงเป็นไม่พร้อมใช้งาน ผู้ผลิตและอินเทอร์เฟซไม่ได้ถูกเปิดเผยโดย Windows เสมอไป เหตุการณ์ที่เกิดขึ้นระหว่างการสแกนทั้งหมดอาจไม่มีใครสังเกตเห็น บันทึกอยู่ในหน่วยความจำและเริ่มต้นหลังจากสินค้าคงคลังสำเร็จครั้งแรก

ตัวระบุบัสและเส้นทางพอร์ตจะอธิบายโทโพโลยีของระบบ ตัวเชื่อมต่อทางกายภาพสามารถมีเส้นทางแยกกันสองเส้นทางสำหรับ USB 2 และ SuperSpeed

## สถาปัตยกรรมและการตรวจสอบ

`scanner.rs` ดำเนินการสินค้าคงคลัง `windows_probe.rs` สรุปคำขออ่านเนทิฟจากฮับ `model.rs` มีข้อมูลและการวินิจฉัย `app.rs` จัดการงานเบื้องหลังและการเลือก `views.rs`, `inspector.rs`, `connection.rs` และ `theme.rs` วาดอินเทอร์เฟซด้วย egui/eframe อินเทอร์เฟซยังคงโต้ตอบระหว่างการสแกนและเก็บการอ่านที่สำเร็จครั้งล่าสุดหากการสแกนครั้งถัดไปล้มเหลว

```powershell
rtk cargo fmt --check
rtk cargo clippy --all-targets -- -D warnings
rtk cargo test --workspace
```

ไลบรารีเป็นแบบข้ามแพลตฟอร์มและโค้ด Windows เป็นแบบมีเงื่อนไข เวอร์ชัน macOS/Linux ไม่ได้รับการตรวจสอบในการจัดส่งครั้งแรกนี้

## การรักษาความลับ

สินค้าคงคลังทำงานในพื้นที่ อ่านอย่างเดียว โดยไม่มีบริการตรวจวัดทางไกลหรือเครือข่าย ลิงก์คำแนะนำจะเปิดเฉพาะเมื่อคลิกเท่านั้น รายงาน JSON สามารถมีหมายเลขซีเรียลและตัวระบุระบบได้ การแชร์จะขึ้นอยู่กับคุณ

## ภาษา — เวอร์ชัน 0.2.0

แอปพลิเคชันประกอบด้วย **50 ภาษาอินเทอร์เฟซ** คลิกรหัสภาษา (`FR`, `EN` ฯลฯ) ที่ด้านบนขวาเพื่อเปิดตัวสลับ คุณสามารถค้นหาภาษาโดยใช้ชื่อท้องถิ่น ชื่อภาษาอังกฤษ หรือรหัส การเปลี่ยนแปลงจะเกิดขึ้นทันทีและตัวเลือกจะถูกเก็บไว้ใน `%APPDATA%/SanUsbViewer/preferences.json` ภายใต้ Windows หากไม่มีการกำหนดค่าตามความชอบ ภาษาของระบบจะถูกใช้ ภาษาที่ไม่รองรับจะเปลี่ยนกลับเป็นภาษาอังกฤษ

ตัวเลือกนี้สนับสนุนภาษาที่พูดมากที่สุดโดยรวม (ภาษาแม่และภาษาที่สอง) โดยจัดกลุ่มตัวแปรภูมิภาคเข้าด้วยกัน นี่ไม่ใช่การจำแนกประเภทตัวเลข: ผลลัพธ์จะแตกต่างกันไปขึ้นอยู่กับการจัดกลุ่มภาษาถิ่น รูปแบบที่เลือก ได้แก่ จีนตัวย่อ อารบิกมาตรฐาน และอักษรละตินของฟูลานีและอุซเบก ปัญจาบใช้ Gurmukhi

อังกฤษ, จีน, ฮินดี, สเปน, ฝรั่งเศส, อาหรับ, เบงกาลี, โปรตุเกส, รัสเซีย, อูรดู, อินโดนีเซีย, เยอรมัน, ญี่ปุ่น, มราฐี, เวียดนาม, เตลูกู, เฮาซา, ตุรกี, ปัญจาบ, สวาฮีลี, ฟิลิปปินส์, ทมิฬ, เปอร์เซีย, เกาหลี, อัมฮาริก, ไทย, ชวา, อิตาลี, คุชราต, กันนาดา, Bhojpuri, พม่า, โปแลนด์, โยรูบา, ลิงกาลา, โอโรโม, ฟูลานี, มาลายาลัม, โอเดีย, ยูเครน, ซินธี, อุซเบก, ปาชโต, ซุนดา, มาเลย์, อิกโบ, เนปาล, อาเซอร์รี, ไมถิลี และโซมาเลีย

เมนู การวินิจฉัย ข้อความช่วยเหลือ ข้อความกิจกรรม และรายละเอียดที่คัดลอกมาจะถูกแปลเป็นภาษาท้องถิ่น ชื่อและตัวระบุที่ได้รับจากฮาร์ดแวร์และระบบจะยังคงอยู่ การส่งออก JSON จะเก็บข้อมูลสคีมาและสินค้าคงคลังไว้ โดยไม่คำนึงถึงภาษาที่แสดง หน่วยทางเทคนิคยังคงอยู่ใน **bit/s** (Mbit/s และ Gbit/s) เพื่อหลีกเลี่ยงความสับสนกับไบต์

แคตตาล็อกภาษาฝรั่งเศสและอังกฤษใช้เป็นข้อมูลอ้างอิง ภาษาอื่นๆ คือ **การแปลอัตโนมัติ** ซึ่งอาจต้องมีการแก้ไขภาษา ไฟล์ `locales/*.json` รวมอยู่ในการคอมไพล์และสามารถแก้ไขแล้วคอมไพล์ใหม่ได้ แอปพลิเคชันไม่มีการแปลเครือข่าย: มีการฝัง 50 ภาษาและแบบอักษร Noto ภายใต้สิทธิ์การใช้งานแบบอักษร SIL Open ข้อความภาษาอาหรับใช้เซ็กเมนต์ Unicode แบบสองทิศทางและการขึ้นบรรทัดใหม่ซึ่งคำนวณก่อนการจัดรูปแบบ

```powershell
# Forcer une langue pour ce lancement, sans remplacer le choix enregistré
rtk cargo run -- --lang ja

# Vérifier les catalogues, les paramètres et les unités de vitesse
rtk python tools/validate_locales.py

# Capture du guide en arabe
rtk cargo run -- --demo --lang ar --page guide --screenshot artifacts/guide-ar.png
```
